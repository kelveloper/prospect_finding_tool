Public Records to Prospect

Four government databases in, one ranked list of physicians worth calling out. Eight numbered steps, three gate layers, and every place a record can be thrown away.

Where it stops being one line

Step 5 is the only fork on the whole chart. Here is one physician’s five rows going through it, so you can point at each row and say where it went.

Reading the fork in one sentence each

The same five rows, in words.

  1. MERGE

    The top path — two rows become one person

    The NPI Registry and IL Licensing both describe the same doctor. Because both rows carry licence 036-104271, they merge with no judgement needed. Output: one person, not two.

  2. ATTACH

    The bottom path — three rows look for an owner

    The PLLC and the two deeds describe things that happened. None of them can create a prospect; each one has to find a person who already exists, or be dropped.

  3. ROW 3

    The billing row attaches on an ID

    Medicare data carries her NPI, so there is zero name risk. And the company is named after her — which is how the system infers she owns her practice.

  4. ROW 4

    The first deed attaches on a name

    Deeds carry no NPI, so this is the one place a name match is unavoidable. It passes because first name, last name and state all match exactly.

  5. ROW 5

    The second deed is thrown out

    Reyes-Martin is close, but not exact. Attaching someone else’s house would silently inflate her score, so the system drops it. This is the strictest rule in the pipeline.

  6. RESULT

    Where 87.7 comes from

    Qualification 95 — physician 40, orthopaedics 35, own PLLC 20. Timing 76.8 — licence 34, property 30, practice entry 12.8. Then 95 × 0.60 + 76.8 × 0.40.

Step by step

Every box on the chart, one line each.

  1. STEP 1

    NPI Registry

    The only source asked a question we invent — every physician in Illinois in these specialties. Everything after this is looked up using IDs this step returns, which is why it must go first.

  2. STEP 2

    IL Licensing

    Queried by the licence numbers from step 1. An exact ID join, so there is no name guessing at all. Adds the licence issue date and whether it is active.

  3. STEP 3

    Medicare Billing

    Queried by the NPI numbers from step 1 — again an exact ID join. Tells us which company gets paid, which is how practice ownership is inferred.

  4. STEP 4

    County Deeds

    Queried by the names from step 1. The only source with no shared ID, which is why it is later held to the strictest matching rule in the system.

  5. STEP 5

    One format

    Four messy feeds become exactly two shapes. A person record is the only kind that can create a new prospect. An event record can only attach to one that already exists.

  6. STEP 6

    One profile

    Licence, practice, company and property in a single file — and every merge and attach logged with a plain-English reason, so any claim traces back to the record behind it.

  7. STEP 7

    Six signals

    Physician, specialty, new licence, owns a practice, bought property, career move. Each rated 0 to 1. No signal means no points — the system never guesses at a missing fact.

  8. STEP 8

    Score, then output

    Should we care? is 60% of the score, why now? is 40%. Out comes a ranked board, a dossier where every fact is sourced, and a contact kit with the practice address and the one trigger to lead with.

Why the sources cannot run at once. Steps 2, 3 and 4 are each looked up using an ID that step 1 hands over — licence numbers, NPI numbers, names. You cannot ask “did this person buy a house?” until you already know who the people are. Three of the four joins are therefore exact-ID matches; only the deeds force a name match.
